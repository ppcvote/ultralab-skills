# Ultra Lab Agent Skills

從真實使用者的生產系統事故裡萃出來的 skill，來自 [Ultra Lab](https://ultralab.tw)。

裡面每一條規則都先付過代價才被寫下來，沒有一條是理論。

## 安裝

```bash
# 全部
npx skills add ppcvote/ultralab-skills

# 單一 skill
npx skills add ppcvote/ultralab-skills --skill verification-discipline
```

## Skills

| Skill | 防的是什麼 | 觸發時機 |
|-------|-----------|---------|
| **verification-discipline** | agent 回報成功、每個檢查都綠燈，而實際上什麼都沒發生 | 「做完了嗎」、驗收、「測試過了但是」、排程沒產出、上線前 |
| **structural-enforcement** | 模型老是做到一半收工；「一定要做 X」的提示失效；強制續跑失控或逼出幻覺 | 「它又停在中間」、「叫它一定要」、Stop hook、安全閥 |

## structural-enforcement

要模型「一定做完某事」，提示保證不了。禁止是單輪決策，義務跨越多輪，任何一輪決定「先回報進度」鏈就斷了。這個 skill 帶的是撐得住的結構做法：

- 禁止與義務的分界，附「提示改三次無效、結構一次就對」的生產實證
- 強制續跑的四道安全閥，以及少一道會壞在哪
- 遞迴陷阱：修正機制的前提不能用模型的自述當判準
- Claude Code 對應：實測過的 Stop hook（`must-finish-guard.py`），只用有文件的原語，不確定一律放行

## verification-discipline

要防的情況是：你的 agent 說任務完成了，狀態端點是綠的，日誌沒有錯誤，而它該做的那件事根本沒發生。

七條規則，每一條都來自真實事故：

1. **驗收要走使用者真正走的那條路。** 一個表單每一層程式碼都正確，程式碼審查看不出問題。用瀏覽器實走才發現對所有使用者都送不出去，因為新集合的資料庫權限規則從來沒加。每一層都 HTTP 200，零筆寫入。
2. **每個檢查都要有陽性對照。** 相信「通過」之前，先證明它會失敗。單頁應用對不存在的路徑回 200 加完整 HTML，而那份 HTML 可能剛好含你要找的字串。
3. **標記完成要在真正完成之後。** 有支程式先把問題標記成已回答再去產生答案。產生那步撞到額度上限，於是問題被永久標記成已處理、永遠不會重試，日誌印的是「沒有新問題」。
4. **計數要量結果，不要量工作量。** 計數器記的是「內容產生完成」而不是「內容真的發出去」，結果壞掉的機器在儀表板上顯示得比健康的還忙。
5. **改共用的東西之前，先找出誰還在用。** 最貴的 bug 不是做錯，是做對一件事卻切斷了下游。
6. **測試失敗時先懷疑測試。** 有一次五個失敗的斷言裡四個是測試自己寫錯。假通過比假失敗更糟，它讓真缺陷帶著綠燈上線。
7. **徹查「為什麼什麼都沒發生」。** 固定的四步順序，因為靜默失敗沒有錯誤訊息可以搜。

附的可執行腳本：

| 腳本 | 用途 |
|---|---|
| `positive-control.sh` | 驗收樣板，檢查無法失敗時直接中止 |
| `number-guard.mjs` | 擋住來源查不到的生成數字，執行即自我測試 |
| `heartbeat-check.sh` | 監控你的監控，包含它自己 |
| `walkthrough.mjs` | 瀏覽器實走並逐步截圖 |

先跑 `node scripts/number-guard.mjs`，它會自我測試六個案例，不需要任何設定。
